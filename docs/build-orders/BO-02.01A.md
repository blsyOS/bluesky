# BO-02.01A — Company Profile Foundation

**Status:** Complete
**Epic:** 02 – Company Administration
**Depends on:** Platform Foundation (Epic 01) complete

## Purpose

The shared Company record every BlueSky product (LocateOS, LeakOS,
FiberOS, …) operates against. This is the company itself — not employees,
not users, not locations. It establishes profile, contact channels,
addresses, branding, preferences, service territory, and feature flags,
plus the Company Administration navigation that future epics extend.

## Architecture

```
prisma: Company (extended)            dba, description, foundedDate,
                                      website, secondary/accent colors,
                                      favicon + email-logo placeholders
        CompanyContactInfo (1:1)      main/emergency/after-hours phones,
                                      main/billing emails
        CompanyAddress (1:n by type)  open `type` string, unique per
                                      company+type; companyLine + street/
                                      city/state/postal/country
        CompanyServiceTerritory (1:1) states/counties (JSON arrays),
                                      description — GIS arrives later
        CompanyFeatureFlag (1:n)      open `key` string, enabled boolean

src/lib/company.ts    ADDRESS_TYPES, KNOWN_COMPANY_FLAGS,
                      COMPANY_DISPLAY_STATUSES — the platform's known sets
src/lib/lists.ts      csv ⇄ JSON-array helpers (shared with Contacts)
src/lib/actions/company-admin.ts   audit-logged actions: profile, contact
                      info, branding, address upsert, territory, flag toggle
src/components/company/
  company-status.tsx     CompanyStatusBadge (trial/active/suspended/
                         archived/expired → design-system tones)
  preferences-panel.tsx  Workspace preferences (shared by /settings and
                         Company → Preferences)
src/app/(app)/company/  Tabbed admin area: Profile | Branding | Addresses |
                         Preferences | Service Territory | Feature Flags
```

## Components / behavior

- **Company Administration navigation**: "Company" added as the first
  Administration entry (all products); `/company` uses the same secondary-
  tab pattern as the Locate module.
- **Profile**: general identity (name, legal name, DBA, status, founded,
  website, description) + contact information panels.
- **Statuses**: settable set is now trial / active / suspended / archived
  (was active / inactive / suspended). "Expired" exists as a derived
  display status. `CompanyStatusBadge` renders all five consistently.
- **Addresses**: one panel per type, generated from `ADDRESS_TYPES` — a
  future type (e.g. "warehouse") is one constant entry, no schema or UI
  changes. Each address carries a printed company line.
- **Branding**: logo + primary/secondary/accent colors with a live brand
  preview; favicon and email-logo fields persist as clearly-marked
  future-ready placeholders. Integration begins: the sidebar company card
  shows the company logo when set.
- **Preferences**: the existing CompanySettings form, extracted into a
  shared panel used by both /settings and Company → Preferences.
- **Service Territory**: states/counties/description foundation.
- **Feature Flags**: per-company toggles (design-system Switch) over the
  `KNOWN_COMPANY_FLAGS` set — foundation only; nothing gates behavior yet.
  Toggles are audit-logged.

## Extension points

- Add an address type → one entry in `ADDRESS_TYPES`.
- Add a feature flag → one entry in `KNOWN_COMPANY_FLAGS`; modules read
  `CompanyFeatureFlag` rows as they come online.
- Add a Company tab → a page under `/company` plus one nav entry in
  `company-nav.tsx`.
- Branding fields are ready for favicon/email/application theming epics.

## Changed existing functionality (documented per the build order)

- **Company statuses** changed from active/inactive/suspended to
  trial/active/suspended/archived. The old "inactive" was never used by
  seeded data; the generic StatusBadge still tones it if encountered.
- **/settings slimmed**: the company-profile form moved to `/company`
  (settings keeps product context + workspace preferences and links to the
  Company area). The BO-01.01 `updateCompany` action remains exported but
  is superseded by `updateCompanyProfile`/`updateCompanyBranding`.
- The Contacts action now uses the shared `lists.ts` helpers (behavior
  identical).

## Known limitations

- Branding applies to the sidebar logo only; favicon, email, and full
  workspace theming are future build orders (fields already persist).
- Service territory is descriptive (no GIS/boundaries).
- Feature flags don't gate behavior yet by design.
- "Expired" is display-only until licensing/billing derives it.
- Single-tenant session still pins the company until auth lands.
