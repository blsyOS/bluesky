# BO-01.03B — Global Search & Command Palette

**Status:** Complete
**Phase:** 01 – Platform Foundation
**Depends on:** BO-01.01, BO-01.01A, BO-01.02, BO-01.03A

## Purpose

The universal search infrastructure for BlueSky OS: a global command
palette (⌘K / Ctrl+K), a modular provider architecture every future module
registers into, quick actions, and the full set of search UI states.
This build order ships architecture and UI only — no business data is
searched. The built-in "platform" provider returns navigation entries to
prove the contract.

## Architecture

```
src/lib/search/
  types.ts          SearchProvider, SearchResult, SearchCategory,
                    QuickAction(+Context), RecentSearch(+Store), groups
  registry.ts       SearchRegistry + app-wide `searchRegistry` singleton
  categories.ts     CORE_CATEGORIES (actions, pages, products, users,
                    companies, projects, tickets, reports, settings)
  recent.ts         RecentSearchStore interface + in-memory placeholder impl
  providers/
    platform.ts     Built-in provider (page navigation) + core quick actions
src/lib/shortcuts.ts  Keyboard shortcut manager (single document listener)
                       + useGlobalShortcut hook
src/components/search/
  search-launcher.tsx     Topbar trigger, ⌘K binding, lazy palette mount
  command-palette.tsx     The modal (combobox/listbox pattern)
  search-result-item.tsx  Reusable result row
  search-states.tsx       Searching / NoResults / NoProviders /
                          NoRecentSearches / AI placeholder
```

**Flow:** modules call `searchRegistry.registerProvider(...)` (usually as a
side-effect import). On query, the registry fans out to all providers with
`Promise.allSettled` (a failing provider is skipped), groups results by
category, sorts groups by category `order` and results by `score`.
Providers never reference each other; adding a category or provider never
modifies existing code.

## Interfaces

- `SearchProvider` — `{ id, label, categories?, search(query) }`; sync or
  async results.
- `SearchResult` — icon/title/description/category/badge/href/keywords/
  score; the palette adds keyboard selection and (future) highlighting.
- `SearchCategory` — id/label/order; core set in `CORE_CATEGORIES`.
- `QuickAction` — `perform(ctx)` receives a UI-agnostic
  `QuickActionContext` (`navigate`, `toggleTheme`, `notify`, `close`), so
  actions stay testable and decoupled from React.
- `RecentSearchStore` — `list/add/clear`; the in-memory implementation is
  deliberately session-only. Persistence lands with authenticated user
  preferences.

## Components

- **SearchLauncher** — the app's single search entry point, mounted once in
  the shell topbar's reserved slot: icon button on mobile, search pill with
  a platform-aware `⌘K`/`Ctrl K` hint on larger screens. The palette module
  is code-split (`next/dynamic`, no SSR) and fetched on first open only.
- **CommandPalette** — modal dialog using the combobox/listbox pattern:
  focus stays in the input, `aria-activedescendant` tracks the active
  option, ArrowUp/Down wrap, Enter activates, Tab/Shift+Tab are trapped
  inside the dialog, Escape and outside-click close, body scroll locks.
  Idle state shows recent searches (with Clear), quick actions, suggested
  pages, and the future-AI placeholder; typing shows a debounced loading
  state then grouped results with matching quick actions first.
- **SearchResultItem** — reusable row: icon bubble, title, description,
  category label, optional badge, accent-bar active state.
- **States** — `SearchingState` (skeleton rows), `NoResultsState`,
  `NoProvidersState`, `NoRecentSearchesState`, `AiPlaceholder`; all built
  on the BO-01.02 EmptyState/Skeleton components.

## Future Dependencies

- Modules (LocateOS, LeakOS, FiberOS, Administration, Reports) register
  providers + categories + quick actions; the palette needs no changes.
- The AI answer surface replaces `AiPlaceholder`.
- Recent-search persistence replaces the in-memory `RecentSearchStore`
  once authentication exists.
- Result-text highlighting hooks into `SearchResultItem` (`title` /
  `description` accept nodes later).
- The shortcut manager is ready for future bindings (e.g. `g d` sequences
  would extend `parseCombo`).

## Known Limitations

- Only the platform navigation provider exists; results are static page
  entries by design.
- Recent searches reset on reload (interface-driven; persistence is a
  later build order).
- The loading state is visible only briefly since the built-in provider is
  synchronous — it exists for real async providers.
- Shortcut manager supports single-chord combos (`mod+k`), not sequences.
- Palette search text is not yet highlighted inside result titles.
