# BO-01.03C — Notification Framework & Activity Center

**Status:** Complete
**Phase:** 01 – Platform Foundation
**Depends on:** BO-01.01 → BO-01.03B

## Purpose

The universal notification framework for BlueSky OS: a provider
architecture every future module registers into, a slide-out notification
center, reusable notification cards with priorities/categories and
read/pin/archive states, and a reusable Activity Center for future
dashboards. This is **not** the delivery engine — no email/SMS/Twilio/push,
no persistence, no user preferences. Placeholder providers prove the
contracts.

## Architecture

  filters.ts      Pure helpers: applyNotificationFilter, sectionNotifications,
                  summarizeNotifications (badge inputs), sortByPriority
  activity.ts     groupActivityByDay (Today/Yesterday/date labels)
  providers/
    platform.ts   Placeholder provider exercising every state + a
                  placeholder activity provider

                            level Escape, focus recovery
src/components/notifications/
  notification-launcher.tsx  Topbar bell + unread/critical badge; owns the
                             single drawer instance (lazy-loaded)
  notification-drawer.tsx    Slide-out center: tabs (Notifications /

## Provider Architecture

Modules call `notificationRegistry.registerProvider(...)` (typically as a
side-effect import, mirroring search). Providers expose `list()` returning
current notifications; the registry merges newest-first and skips failing
providers. `registerActivityProvider(...)` feeds the Activity Center the
same way. Categories auto-register from providers; the center renders
whatever categories exist — adding modules never modifies this code.

## Components

- **NotificationLauncher** — bell with count badge (blue; red when an
  unread critical exists, plus a spoken "includes critical" aria-label).
  The drawer chunk is code-split and loads on first open.
- **NotificationDrawer** — right-hand slide-out (animated, portaled to
  body, focus-trapped, document-level Escape, outside-click close, body
  scroll lock, full-width on mobile / 28rem panel on ≥sm). Header shows
  unread count and Mark-all-read. Tabs: Notifications and Activity.
  Filter framework: All / Unread / Pinned / Archived chips plus category
  and priority selects — state is session-only by design. The All view
  renders Pinned → Unread → Recent sections; other views render flat
  lists. Empty, loading, and no-providers states included.
- **NotificationCard** — icon, title, description, relative timestamp,
  PriorityBadge, category chip, pinned/archived chips, unread dot +
  accent tint, action-button placeholder (informational toast), and
  Mark read/unread · Pin · Archive controls. Product accents flow through
  `accentKey` → `accentStyle()`.
- **ActivityCenter** — reusable date-grouped feed (Today / Yesterday /
  date) with loading skeleton and empty state; consumes any
  `ActivityEntry[]` so future dashboard widgets reuse it directly.

## Extension Points

| Seam | How future modules plug in |
| --- | --- |
| Notification providers | `notificationRegistry.registerProvider()` |
| Categories | `registerCategory()` or `provider.categories` |
| Priorities | Fixed five-level scale; display via `PRIORITY_META` |
| Actions | `notification.action` (placeholder until module handlers land) |
| Activity feed | `registerActivityProvider()` |
| Dashboard widgets | `<ActivityCenter />` + `<NotificationCard />` are standalone |

## Known Limitations

- Read/pin/archive state is session-only (in `useNotificationCenter`);
  persistence arrives with authenticated user preferences.
- Action buttons show an informational toast — real handlers are a module
  concern.
- No pagination or virtualization; fine at placeholder volumes, revisit
  when real providers ship meaningful volume.
- The bell badge loads provider data on shell mount; today that is a
  static in-memory list. When providers become async/remote, consider a
  lighter count endpoint.
- Notification delivery (email/SMS/push/Twilio), scheduling, and
  preferences are explicitly out of scope.
