# BO-02.01B — Platform vs Organization Administration Scaffold

**Status:** Complete
**Epic:** 02 – Company Administration
**Depends on:** BO-02.01A (Company Profile Foundation)

## Purpose

Separates the two administration scopes the platform will always have:

- **Organization Administration** — what each tenant manages about
  itself: organization profile, products, users, roles, audit logs,
  settings. Requires `company.manage`. Lives at `/company` and the other
  existing admin routes.
- **Platform Administration** — what BlueSky staff manage across all
  tenants: companies, product catalog, licensing, billing, feature
  management, system health, support tools. Requires `platform.manage`.
  Lives under `/platform`.

This build order is a *scaffold*: the Platform area's navigation,
permission gating, and page shells are real; only the Companies page has
live data. Everything else is an explicit placeholder that states what
will appear and which future build order supplies it. No billing, no
licensing enforcement, no company-creation wizard, no cross-company
dispatch.

## The two admin scopes

```
Sidebar (per session, appended after product sections):

  Organization      requires company.manage      (every tenant's admins)
    Organization        /company        tenant's own record (BO-02.01A)
    Products            /products
    Users               /users
    Roles & Permissions /roles
    Audit Logs          /audit-logs
    Settings            /settings

  Platform          requires platform.manage     (BlueSky staff only)
    Companies           /platform/companies   REAL: lists all tenants
    Product Catalog     /platform/catalog     placeholder
    Licensing           /platform/licensing   placeholder
    Billing             /platform/billing     placeholder
    Feature Management  /platform/features    placeholder
    System Health       /platform/health      placeholder
    Support Tools       /platform/support     placeholder
```

- `src/lib/products/admin-nav.ts` defines `ORG_SECTION`,
  `PLATFORM_SECTION`, and `adminSectionsFor(access)` which returns only
  the sections the session may see. `resolveSidebar` now appends an
  *array* of admin sections (was a single hard-coded one).
- `src/app/(app)/layout.tsx` computes `AdminAccess` from session
  permissions (`company.manage`, `platform.manage`) and passes it into
  the shell — the sidebar never renders a section the user can't open.
- Navigation hiding is not security: `src/lib/authz.ts
  requirePermission(key)` guards the `/platform` and `/company` layouts
  server-side and 404s (`notFound()`) without the permission, so direct
  URL entry is also blocked.

## Wording: "Organization" vs `Company`

UI wording is now **Organization** (sidebar section, `/company` page
header/description, breadcrumb, settings pointer card). The database
models keep their `Company*` names — renaming Prisma models would churn
every query for zero behavioral gain. The rule: *say organization, store
Company.*

## The BlueSky Locating rule

**BlueSky Locating is a normal tenant inside BlueSky OS.** It is a
customer of the platform like any other company:

- It uses the same products (LocateOS, LeakOS, FiberOS, …) any customer
  can license — no special-cased code paths, models, or flags.
- There is **no separate dispatch portal in the MVP**. If BlueSky
  dispatches for ABC Locating, those dispatch users are provisioned as
  users *inside ABC Locating's tenant* and operate entirely within it.
- A cross-company dispatch command center (one BlueSky operator working
  tickets across many tenants) is **future scope** and will be designed
  as a platform-level capability when it arrives — not by weakening
  tenant isolation now.

What makes BlueSky-the-company different is only that its staff hold
`platform.manage` and therefore see the Platform section. That is a
permission, not a tenant type.

## Tenant isolation

- Every operational record (users, products, contacts, addresses, flags,
  audit logs, …) is keyed by `companyId`; all queries in tenant-facing
  pages and actions filter through the session's company.
- The Platform area is the *only* place that reads across tenants (the
  Companies page does `company.findMany` with counts), and it sits
  behind `platform.manage`.
- Future platform tools that act *on* a tenant (support impersonation,
  data repair) must be audit-logged and enter through the tenant's own
  context rather than bypassing it.

## Components / behavior

- **`/platform` layout**: `requirePermission("platform.manage")`, page
  header with a "Platform admins only" badge, seven secondary tabs.
  `/platform` redirects to `/platform/companies`.
- **Companies page (real)**: all tenants with name, slug, subdomain,
  status (`CompanyStatusBadge`), enabled-products count (active/trial)
  + user count, created date. Row actions View / Manage / Suspend /
  Billing are placeholders that toast which build order delivers them.
- **Placeholder pages**: shared `PlatformPlaceholder` renders the empty
  state plus a "Planned functionality" list — no invented data, per the
  standing rule.
- **Shared `TabNav`** (`src/components/tab-nav.tsx`): the secondary-tab
  pattern extracted from Company/Locate navs; all three areas
  (Organization, Locate, Platform) are thin wrappers over it.

## Extension points

- New Platform tool → page under `/platform/*` + one `PLATFORM_SECTION`
  entry.
- New Organization page → same, via `ORG_SECTION`.
- A third admin scope (e.g. reseller) → new section + one boolean on
  `AdminAccess`; `adminSectionsFor` composes it.
- Companies-page actions are the seams for company management, licensing
  and billing build orders.

## Changed existing functionality (documented per the build order)

- `resolveSidebar(config, adminSections)` takes `NavSection[]` instead
  of a single section (tests updated).
- The always-visible "Administration" sidebar section is replaced by the
  permission-scoped Organization/Platform sections; `ADMIN_SECTION` is
  no longer exported.
- `/company` UI wording changed to "Organization" (header, breadcrumb,
  settings pointer). Routes and models are unchanged.
- `/company` now server-guards on `company.manage` (previously reachable
  by any session).

## Known limitations

- Placeholder actions and pages do nothing yet by design.
- The single seeded session holds both permissions, so the "org-only"
  sidebar is verified by unit tests (`adminSectionsFor`) rather than a
  second live login until auth lands.
- Suspend/status changes from the Companies page arrive with the company
  management build order; licensing/billing enforcement later still.
