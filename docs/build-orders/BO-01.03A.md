# BO-01.03A — Application Navigation Framework

**Status:** Complete
**Phase:** 01 – Platform Foundation
**Depends on:** BO-01.01, BO-01.01A, BO-01.02

## Purpose

Finish the permanent navigation shell that every future BlueSky OS module
inherits: sidebar, top navigation, breadcrumbs, user profile menu, product
switcher, and mobile navigation. Later build orders (Company Administration,
LocateOS, LeakOS, FiberOS, SiteView, Command Center) plug pages into this
shell without touching navigation code.

## Scope

In scope: sidebar collapse/expand with persistence, icon-only mode, nav
section headers, improved active indicator, top navigation layout
(breadcrumbs / reserved search slot / actions cluster), reusable breadcrumb
framework, user profile menu (UI only), product switcher status display,
mobile drawer animation and touch targets, keyboard accessibility.

Out of scope (future build orders): Search, Command Palette, Notifications,
Favorites, Recently Viewed, and all operational modules.

## Architectural Decisions

1. **Sidebar state persists in a cookie, not localStorage.** The server
   reads `bsky_sidebar` in the layout and passes `initialCollapsed`, so SSR
   renders the persisted state directly — no post-hydration effect, no
   layout flash, and no `setState`-in-effect lint violations.
2. **Breadcrumbs derive from the URL, not per-page configuration.**
   `AutoBreadcrumbs` maps route segments through a label table and resolves
   product keys to display names. Pages can still pass manual crumbs via
   `PageHeader`, which delegates to the same presentational component
   (one renderer, two entry points).
3. **Popover behavior extracted to `usePopover`.** The product switcher and
   user menu share dismissal semantics instead of duplicating listeners.
4. **Product availability wording centralized.** `describeAvailability()`
   in `lib/access.ts` is the only place that maps licensing state to a
   label + tone; the switcher dropdown and product cards both consume it.
5. **The topbar reserves a center slot** (`data-slot="search"`) and the
   right-side cluster is ordered so a notifications button can slot in
   before the theme toggle without relayout.
6. **Mobile drawer stays mounted** and animates via transform/opacity,
   with `inert` + `aria-hidden` while closed so hidden links are neither
   focusable nor announced.

## Future Dependencies

- Global Search / Command Palette mounts into the topbar center slot.
- Notifications mounts into the right cluster before the theme toggle.
- Product modules get breadcrumbs by extending `ROUTE_LABELS` or the
  product-name map already passed to `AutoBreadcrumbs`.
- User menu placeholder items (Profile, Preferences, Shortcuts, Help) are
  wired to real surfaces when those build orders land.

## Known Limitations

- User menu items are UI placeholders; clicking shows an informational
  toast. Logout routes to the placeholder login page (no real session).
- Dropdown menus support Escape/outside-click/Tab but not arrow-key
  roving focus; acceptable at current menu sizes, revisit with the
  command palette build order.
- `AutoBreadcrumbs` renders raw segment text for unmapped deep routes
  (e.g. future `/users/<id>`); those pages should extend the label map
  or override via `PageHeader` breadcrumbs.
- Collapsed sidebar relies on `title` tooltips; a styled tooltip
  component is future design-system inventory.
